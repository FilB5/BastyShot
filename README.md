
# BastyShot 🔒📸
**Децентрализованный скриншотер с Zero-Knowledge шифрованием для экосистемы Bastyon.**

BastyShot позволяет делать скриншоты, редактировать их, распознавать текст (OCR) и публиковать в децентрализованную сеть IPFS. Все скриншоты шифруются локально (AES-GCM), гарантируя, что никто, кроме владельца ссылки, не сможет просмотреть изображение.

## 🌟 Ключевые особенности
- **Zero-Knowledge Шифрование:** Скриншоты шифруются на устройстве пользователя до загрузки в сеть IPFS. Ключ расшифровки хранится в ссылке (после символа `#`), который не передается на сервер.
- **Двойная защита (Key Wrapping):** Возможность защитить скриншот паролем. Ключ картинки шифруется ключом, выведенным из пароля (PBKDF2).
- **Интеграция с IPFS:** Загрузка через Pinata API или собственные шлюзы.
- **Встроенный OCR:** Распознавание текста с экрана локально с помощью Tesseract.js (работает офлайн после скачивания словарей).
- **Переводчик:** Мгновенный перевод распознанного текста прямо на скриншот (Google, Lingva, MyMemory API).
- **Приватность:** Никакой телеметрии, никаких сторонних серверов для хранения изображений.

## 🛠 Технологический стек
- **Backend:** Go (Wails v2)
- **Frontend:** Vanilla JS, Fabric.js, Tesseract.js
- **Crypto:** AES-GCM, PBKDF2 (через Web Crypto API и Go crypto)
- **Network:** IPFS (Pinata), HTTP/SOCKS5 Proxy support

## 🚀 Как собрать из исходников
1. Установите [Go](https://go.dev/dl/) (рекомендуется версия 1.21 или 1.22) и [Node.js](https://nodejs.org/) (v18+).
2. Установите Wails CLI:
   ```bash
   go install github.com/wailsapp/wails/v2/cmd/wails@latest
   ```
3. Клонируйте репозиторий:
   ```bash
   git clone https://github.com/FilB5/BastyShot.git
   cd BastyShot
   ```
4. Установите зависимости фронтенда:
   ```bash
   cd frontend
   npm install
   cd ..
   ```
5. Соберите проект:
   ```bash
   wails build
   ```
Готовый `.exe` файл появится в папке `build/bin/`.

## ⚠️ Конфиденциальность переводчика
Использование функции перевода отправляет распознанный текст на серверы Google/MyMemory. Это нарушает режим Zero-Knowledge для текстовой части скриншота. Пользователь всегда предупреждается перед использованием переводчика.

## 🛡 Архитектура безопасности (Zero-Knowledge IPFS Publishing)

BastyShot построен на архитектуре Zero-Knowledge (Нулевого разглашения). Это означает, что серверы IPFS (шлюзы и пиннинг-сервисы) хранят только зашифрованные данные и никогда не имеют доступа к ключам расшифровки или исходным изображениям. Вся криптография происходит на стороне клиента (в памяти ПК пользователя или в браузере просматривающего).

### Основные криптографические примитивы
1. **AES-256-GCM** (Advanced Encryption Standard, Galois/Counter Mode) — симметричное шифрование для самих данных изображения. GCM обеспечивает как конфиденциальность, так и аутентификацию (защиту от подмены данных).
2. **PBKDF2** (Password-Based Key Derivation Function 2) с HMAC-SHA256 — алгоритм вывода ключа из пароля (KDF). Используется 100 000 итераций для защиты от брутфорса.
3. **CSPRNG** (Cryptographically Secure Pseudo-Random Number Generator) — генерация случайных ключей и солей (`crypto/rand`).
4. **Base64URL** — кодирование бинарных данных (ключей, шифротекста) для безопасной передачи в URL и HTML.

### Режимы публикации
BastyShot поддерживает три режима публикации, каждый из которых имеет свой уровень безопасности.

#### Режим 1: Стандартный (Без пароля)
**Назначение:** Быстрый обмен скриншотом без необходимости вводить пароль.

**Механика:**
1. Программа генерирует случайный 256-битный ключ (`ImgKey`) и 96-битный `Nonce` с помощью CSPRNG.
2. Изображение шифруется с помощью AES-256-GCM используя `ImgKey` и `Nonce`. Полученный шифротекст (Ciphertext) встраивается в HTML-страницу.
3. `ImgKey` кодируется в Base64URL и помещается в фрагмент URL (после символа `#`).
4. HTML-файл загружается в сеть IPFS.
5. Просмотр: Браузер скачивает HTML, извлекает ключ из `#`, расшифровывает картинку в памяти (WebCrypto API) и отображает.

**Безопасность:** Стандартный уровень. Сервер IPFS не видит ключ (он в `#`). Однако, если ссылку перехватят в мессенджере, у перехватчика будет и файл, и ключ.

#### Режим 2: Короткая ссылка (Только пароль)
**Назначение:** Максимальная защита от перехвата ссылки в мессенджерах.

**Механика:**
1. Программа генерирует случайную 128-битную `Salt` (соль).
2. Из пароля пользователя с помощью PBKDF2 (100 000 итераций, SHA-256) выводится 256-битный `PwdKey`.
3. Изображение шифруется с помощью AES-256-GCM, используя `PwdKey`.
4. В HTML встраивается шифротекст, `Nonce` и `Salt`.
5. Ключ в ссылку не помещается! Ссылка выглядит как `.../CID` (без `#`).
6. Файл загружается в IPFS.
7. Просмотр: Браузер скачивает HTML, запрашивает пароль, генерирует `PwdKey` из пароля и соли, расшифровывает картинку.

**Безопасность:** Высокий уровень. Если ссылку перехватят, у злоумышленника будет только адрес файла. Чтобы расшифровать его, он должен подобрать пароль (защищен PBKDF2).

#### Режим 3: Гибридный (Ссылка + Пароль / Key Wrapping)
**Назначение:** Двойная защита. Ключ спрятан в ссылке, но "заперт" паролем.

**Механика (Key Wrapping):**
1. Программа генерирует случайный 256-битный `ImgKey` (ключ для картинки) и шифрует само изображение (AES-256-GCM).
2. Генерируется `Salt` и из пароля выводится `PwdKey` (как в Режиме 2).
3. Шифрование ключа: Программа шифрует сам `ImgKey` с помощью `PwdKey` (используя отдельный `KeyNonce`). Получается `EncryptedImgKey`.
4. В HTML встраивается шифротекст картинки, `Nonce`, `Salt` и `KeyNonce`.
5. В ссылку (в `#`) помещается `EncryptedImgKey`.
6. Файл загружается в IPFS.
7. Просмотр: Браузер скачивает HTML. Страница запрашивает пароль. Из пароля и соли генерируется `PwdKey`. Этим ключом расшифровывается `EncryptedImgKey` (извлеченный из `#`), чтобы получить оригинальный `ImgKey`. И только потом этим `ImgKey` расшифровывается сама картинка.

**Безопасность:** Очень высокий. Чтобы открыть картинку, нужны и ссылка (где лежит зашифрованный ключ), и пароль. Перехват ссылки бесполезен без пароля. Поиск файла в IPFS бесполезен без ссылки (ключа нет). Единственный способ взлома — брутфорс пароля.

### Защита метаданных (EXIF)
BastyShot работает с PNG-скриншотами, которые изначально не содержат EXIF-данных (GPS, модель камеры и т.д.). Кроме того, изображение перед шифрованием декодируется в Canvas и кодируется заново, что физически уничтожает любые скрытые метаданные. В IPFS загружается только чистый шифротекст, упакованный в HTML.

### Транспортная безопасность (IPFS)
Загрузка файлов в IPFS (через Pinata API) и просмотр их через шлюзы (dweb.link, etc.) происходит по HTTPS. Однако, благодаря Zero-Knowledge архитектуре, даже если HTTPS будет скомпрометирован, злоумышленник получит доступ только к зашифрованному HTML-файлу.
